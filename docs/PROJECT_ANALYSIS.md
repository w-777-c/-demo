# 项目分析与完善记录

## 原始项目的目的

这是一个用于学习 Java 基础的控制台回合制格斗 demo。原入口 `App` 调用 `Login`，使用内存列表完成注册登录，再进入 `FightingGame`。`Character` 提供生命、攻击、防御；`HeroCharacter` 与 `EnemyCharacter` 继承角色基类，敌人的 `takeDamage` 演示方法重写和多态。玩家分配属性后，通过普通攻击、强力一击和生命汲取连续挑战随机敌人。

练习点包括封装、继承、多态、集合、循环、条件分支、随机数以及控制台输入。原项目只有 Java 源码、IDEA 模块文件和编译产物，没有构建脚本或有效测试。

## 发现的问题与处理

| 原始问题 | 影响 | 当前处理 |
| --- | --- | --- |
| 在多个方法中反复创建 `Scanner(System.in)` | 多重缓冲会干扰输入，重定向输入尤其容易失败 | 控制台共享输入实例，统一按行读取 |
| 属性点直接调用 `nextInt()` | 输入文字或超大数字直接异常退出 | 范围校验，错误重试，EOF 正常结束 |
| 注册账号只放在方法内的 `ArrayList` | 重启全部丢失 | 账号和累计战绩保存到本地文件 |
| 用户保存明文密码 | 不适合作为持久化账号实现 | PBKDF2、独立随机盐、摘要校验 |
| 密码输错三次永久禁用，要求联系客服 | 单机 demo 没有客服或解锁流程，用户无法恢复 | 移除虚假的永久禁用和本地验证码流程 |
| 每三胜只给 `HP` 加20，没有修改 `maxHP`，提示却写加30 | 血量超过上限，后续治疗甚至降低生命值 | 封装升级，最大生命与当前生命统一增加30 |
| 生命汲取消耗10生命并随机恢复0-20，没有攻击 | 技能含义与效果不一致，可能越用越亏 | 实际造成伤害，按实际伤害回血，添加冷却 |
| 打印的伤害没有考虑防御姿态或剩余生命，回血也没有考虑上限 | 日志与角色状态不一致 | 伤害和治疗方法返回实际变化值 |
| 技能条件不满足仍进入敌方回合 | 无效选择也受到惩罚 | 先验证行动，失败不推进回合或冷却 |
| 角色属性全部公开可写 | 任意调用方能破坏生命上下限等约束 | 私有字段，提供受控的战斗与成长方法 |
| 敌人对象复用并由 UI 修改成长属性 | 状态容易泄漏到下一场，规则难以测试 | 每场从基础模板生成新的敌人 |
| 结束游戏直接 `System.exit(0)` | 不能再次开局或切换账号 | 正常结算后回到可再次开局的状态 |
| 控制台 UI、战斗规则、成长和输入耦合 | 难以扩展成图形版，测试必须模拟所有输入 | 拆出 `Battle`、`GameSession` 和 `UserStore` |

## 桌面版设计

根据本次明确的方向，默认入口改为 Swing 桌面游戏。首屏直接展示竞技场，游客可以开局，账号功能位于顶部。中间显示角色、动态血条、敌方状态与回合；下方提供技能按钮和战斗记录；右侧展示局内属性、个人纪录与继续/结算按钮。

角色与场景采用原创 Java2D 像素画。Swing 定时器驱动轻量待机动画，窗口销毁时停止。密码验证和密码摘要生成放入 `SwingWorker`，避免阻塞界面事件线程。窗口最小尺寸为1000×760，并对按钮文本和属性区做布局检查。

后续 UI 优化增加了统一主题、关卡进度条、技能消耗与冷却说明、悬停和键盘焦点状态、按列对齐的玩家属性。竞技场加入石墙与拱门，敌人的武器和护甲区分职业；攻击动作、血条过渡和生命变化提示由界面层驱动，生命变化提示显示本回合前后的净变化（包含技能费用、回复或战后奖励），不会改变战斗判定。战绩表支持按列排序，数值按数字比较；登录与注册使用分段切换，弹窗和表格保持深色主题。

## 状态与边界

`GameSession` 包含战斗中、战间休息和已结束三种状态。只有战斗中可以执行技能，只有休息时可以进入下一场；胜利奖励只发放一次。失败、主动撤退与十关通关进入结束状态。桌面与控制台入口共用这套逻辑。

存储读取会检查版本、必需字段、用户名、密码摘要结构和战绩数值。读取失败不会自动覆盖原存档。写入先创建同目录临时文件，再替换目标；启动时持有数据目录的文件锁，避免多个应用实例相互覆盖。

最高连胜榜把十关挑战与无尽试炼合并统计，通关次数单独统计。升级属于单局成长，新开一局重新分配属性。当前没有局中断点存档、联网对战、账号恢复和声音资源。

## 验证方式

运行 `run.ps1 -Test` 检查生命边界、防御消耗、技能费用、汲取实际回血、冷却、无效行动、死亡后停止行动、升级、十关通关、无尽模式、密码摘要、存档重载、损坏文件保留、非法输入和 EOF。

运行 `run.ps1 -GuiTest` 打开真实 Swing 窗口，执行注册、创建角色、鼠标攻击、技能冷却、首战胜利、下一场、缩小窗口、撤退、战绩保存、退出账号、重新登录和战绩榜。截图写入 `build/screenshots`，供人工检查；测试同时校验渲染非空、按钮文本宽度和属性区域尺寸。

桌面验证还覆盖技能副标题的宽度、所有可见标签的边界，以及两帧之间的攻击和血条动画变化。登录、建角、战绩榜均单独生成截图；主界面截图同时覆盖默认尺寸与1000×760的最小尺寸。

当前环境使用 PyCharm 自带的 JBR 25 编译和运行，编译目标通过 `--release 17` 限定为 Java 17。测试不依赖 JUnit 或其他外部库，失败会返回非零退出码。

# 共享画板协议 v1

端点：`/ws/board`。所有消息使用 JSON 文本帧；浏览器采用同源连接。回声端点 `/ws/echo` 保持原行为。

## 客户端请求

绘画请求：

```json
{
  "v": 1,
  "type": "draw",
  "opId": "17",
  "epoch": 0,
  "tool": "pen",
  "color": "#148579",
  "width": 6,
  "points": [[120, 180], [126.5, 190]]
}
```

`opId` 是当前连接内唯一的操作 ID，限 1–64 位字母、数字、下划线或连字符。`epoch` 必须等于最近快照或清空事件中的画布版本。`tool` 为 `pen` 或 `eraser`；橡皮最终颜色由服务端固定为白色。`color` 接受六位十六进制颜色，`width` 必须是 1–32 的整数。

每条绘画消息携带 1–32 个点。坐标限定为 x=0–1200、y=0–720 的有限数字，服务端统一四舍五入到 0.1 像素。单点绘制圆点，多点用圆头圆角折线绘制。浏览器约每 32ms 发送一批点；同一笔相邻批次保留一个公共端点，最终图像以服务端广播为准。

| 请求 | 字段 | 行为 |
| --- | --- | --- |
| `draw` | 上述字段 | 校验并追加一个绘画片段，向所有人广播，包括发送者 |
| `clear` | `v`, `type`, `opId`, `epoch` | 清空片段，递增画布版本和事件序号，向所有人广播 |
| `sync` | `v`, `type` | 向当前连接发送完整快照 |
| `ping` | `v`, `type` | 回复 `pong`，不修改画布 |

服务端没有信任客户端提供的用户 ID，广播中的 `clientId` 由每次连接建立时生成。

## 服务端事件

首次连接时，先收到：

```json
{
  "v": 1,
  "type": "snapshot",
  "seq": 18,
  "epoch": 2,
  "width": 1200,
  "height": 720,
  "clientId": "server-assigned-uuid",
  "segments": [],
  "maxSegments": 2000,
  "maxPoints": 20000
}
```

`segments` 是按服务端接受顺序排列的片段数组，每项包含 `opId`、`clientId`、`tool`、`color`、`width` 和 `points`。

| 事件 | 主要字段 | 含义 |
| --- | --- | --- |
| `snapshot` | 上述字段 | 替换客户端整个画布和本地序号 |
| `draw` | `seq`, `epoch`, `segment` | 按顺序绘制已校验的片段 |
| `clear` | `seq`, `epoch`, `opId`, `clientId` | 清空图像并取消尚未完成的本地笔迹 |
| `presence` | `count` | 当前画板连接数，每个标签页算一个连接 |
| `ack` | `opId`, `seq` | 重复操作已处理，不再广播或修改画布 |
| `error` | `code` | 请求被拒绝，不改变画布或序号 |
| `pong` | 无额外字段 | 心跳回复 |

所有事件均包含 `v: 1` 和 `type`。`seq` 仅在接受绘画或清空操作后递增，清空时不重置。客户端发现序号不连续时暂停绘画并请求快照。心跳、在线人数、错误和快照本身不占用事件序号。

错误码：`BAD_MESSAGE`（字段或 JSON 不合法）、`STALE_EPOCH`（旧版本操作，随后补发快照）、`BOARD_FULL`（画布容量已满）。

## 顺序与并发

单个服务进程只有一个公共画板。状态更新、递增 `seq`、创建快照和投递到客户端队列在同一个锁内完成。因此新用户快照之后的第一个绘画事件恰好接续快照序号，不会遗漏或重复。

每个连接使用独立的 FIFO 发送队列和单个发送线程。广播只投递队列，网络 I/O 不持有画板锁；同一 WebSocket 不会出现多个线程并发调用 `sendMessage`。

清空会递增 `epoch`。清空前已经接受的绘画排在清空事件前面；清空后才到达的旧版本绘画被拒绝，不会让旧笔迹重新出现在画面上。

同一连接最近 256 个已接受的 `opId` 用于去重。重复请求仅回复 `ack`。这是有界去重窗口，不承诺跨连接或超过窗口的恰好一次执行。浏览器在重连后直接加载快照，不重发旧操作。

## 容量与连接

- 单条入站消息最多 8192 个 UTF-8 字节，超限关闭码 `1009`；二进制帧关闭码 `1003`。
- 同时最多 24 个画板连接。容量已满时新连接以 `1013` 关闭。
- 最多保存 2000 个片段、20000 个点，任一上限到达后拒绝新增片段，仍可清空及请求快照。不会静默删除旧笔迹。
- 每个连接最多排队 128 条事件、2MiB 数据；慢客户端超过任一上限后断开（`1013`），重连获取快照。
- 浏览器每 25 秒发送心跳，超过 65 秒没有收到消息则重连；重连退避从 1 秒增加到最多 8 秒。手动断开后停止重试。
- 服务器不持久化画板。重启服务会清空图像，序号和画布版本从零开始；新快照始终覆盖旧状态。

当前没有账号鉴权、限频、公平调度或多进程状态协调，适合本机与可信局域网原型验证。后续游戏回合及房间状态应继续复用服务端校验和有序事件的方式维护。

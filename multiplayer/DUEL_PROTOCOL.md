# 联机格斗协议 v1

页面 `/duel.html`，WebSocket 端点 `/ws/duel`，采用同源 JSON 文本消息。

## 身份与席位

连接后发送 `{"v":1,"type":"hello","resumeToken":""}`。服务端回复 `welcome`，包含 `yourSeat`（-1 观战、0 为 P1、1 为 P2）、`resumeToken`、`resumeError` 和完整 `state`。

新连接默认观战；发送 `join` 并提供 1–16 位昵称后占用空席，只有给该连接的 `welcome` 包含随机恢复凭据。公开状态、战斗日志和广播均不包含凭据。昵称允许文字、数字、空格、下划线和连字符，不能为空白。

重连时在 `hello` 中携带原凭据。席位仍有效时恢复身份；若旧连接还在线，则用关闭码 `4001` 终止旧连接，旧连接不能继续控制角色。旧页面收到该关闭码后停止自动恢复并清除自身凭据，避免两个标签页反复争用席位。失效凭据返回观战身份及 `SEAT_EXPIRED`，可重新入席。

恢复凭据是短期的席位持有凭证，不是用户账号认证。只存储在当前标签页的 `sessionStorage`，不放入 URL。

## 操作

所有消息带 `v:1`。除 `hello`、`ping`、`sync` 外，每条请求必须提供当前连接内唯一的 `opId`，限定为 1–64 位字母、数字、下划线或连字符。

| 类型 | 其他字段 | 行为 |
| --- | --- | --- |
| `join` | `name` | 占用一个空席，不接受客户端选择席位或属性 |
| `ready` | `matchId` | 设置准备；双方在线且准备后开战 |
| `action` | `matchId`, `turn`, `action` | 只允许当前回合所属席位使用可用技能 |
| `resign` | `matchId` | 战斗中认输，暂停时也可认输 |
| `rematch` | `matchId` | 本局结束且双方在线时申请再战，双方同意后重置角色并轮换先手 |
| `leave` | 无 | 立即释放本人席位；战斗中离开会判负 |
| `sync` | 无 | 获取当前完整状态 |
| `ping` | 无 | 回复 `pong`，不改变战斗状态 |

```json
{
  "v": 1,
  "type": "action",
  "opId": "operation-7",
  "matchId": "server-assigned-match-uuid",
  "turn": 3,
  "action": "ATTACK"
}
```

`action` 为 `ATTACK`、`POWER_STRIKE`、`DRAIN`、`DEFEND` 或 `POTION`。属性、伤害、血量、冷却和药水数量完全由服务端维护，客户端提交的同名字段不会用于结算。服务端将连接映射到席位，不信任请求中的玩家编号。

接受操作后广播完整 `state`，并向发起者发送 `ack`（`opId`, `revision`）。同一连接最近 256 个已接受的操作 ID 去重；重复请求只补发状态和确认，不再次结算。重连不重发未确认操作，而是以服务端状态为准。回合和对局 ID 会进一步拒绝迟到的操作。

拒绝请求时只回复 `error`，包含 `code`、`opId` 和最新 `state`，不修改血量、回合或资源。常见代码包括 `NOT_SEATED`、`NOT_YOUR_TURN`、`STALE_TURN`、`STALE_MATCH`、`SKILL_UNAVAILABLE`、`ARENA_FULL`。

## 权威状态

`state` 包含：

- `matchId`：对局 ID，新对手加入已结束的竞技场或开始再战时更新。
- `revision`：所有有效状态变化的递增版本，包括连接状态和准备状态。客户端只渲染收到的状态，不预测血量或胜负。
- `phase`：`WAITING`、`FIGHTING`、`PAUSED`、`FINISHED`。
- `turn`、`activeSeat`：当前行动回合和所属席位。每次有效行动交换玩家。
- `winner`、`reason`：结算席位（-1 为无胜者或平局）及原因，只在 `FINISHED` 时解释为最终结果。
- `fighters`：已占席角色的公开数据，包括昵称、在线状态、重连截止时间、准备/再战意愿、生命、攻防、药水、冷却、防御姿态和技能可用性。
- `log`：最近 80 条记录，包含独立递增 ID、回合和文字。
- `serverTime`：服务器时间，用于显示重连倒计时；客户端倒计时不会自行判定胜负。

双方初始为均衡角色（180 HP、30 ATK、2 DEF、3 瓶药水），直接复用原项目 `HeroCharacter` 和 `CombatRules`。原 `Battle` 继续负责单机 AI 回合，联机 `DuelArena` 负责轮流行动。

断线后保留席位 30 秒并暂停未结束的战斗。服务端定时检查期限，任何请求处理前也检查期限。过期判负并释放席位；双方席位均释放时竞技场回到等待状态。准备阶段断线取消该玩家的准备。没有行动计时器；达到 200 次有效行动仍无击杀时判平局。

## 并发与边界

对局命令、连接恢复、断线处理、超时结算和状态快照都在 `DuelHandler` 的同一把锁内执行。校验与状态变更不可被其他线程插入。广播在锁内投递至 `SessionSender`，每个连接使用独立 FIFO 队列和单个线程进行实际网络发送，不让慢连接占用对局锁。

最多 24 个连接（包括观战）；每条入站消息最多 4096 个 UTF-8 字节。超限关闭码为 `1009`，二进制帧为 `1003`；慢客户端或连接满时为 `1013`。发送队列沿用 128 条或 2MiB 上限。

浏览器每 25 秒发送心跳，超过 65 秒未收到消息则重连。自动重连退避为 1–8 秒；操作确认超过 8 秒时通过重连重新获取状态。服务器空闲连接期限为 120 秒。

当前只支持单进程、单公共竞技场，状态不落盘。服务重启后对局及凭据失效。这一步没有多房间、匹配、账号、战绩和多实例协调。

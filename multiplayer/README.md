# 铁境竞技场 / 最小联机对战原型

基于原格斗项目的 Java WebSocket 联机原型。已完成回声验证、共享画板练习和服务端权威的双人格斗。画板仅用于验证通信链路，最终游戏围绕原来的格斗玩法推进。

桌面版和联机版共用 `fightinggame/src/com/itheima/game/CombatRules.java` 技能结算与角色模型。联机版只编译所需的战斗源码，不加载 Swing 界面或本地账号存档。尚未加入多房间、匹配、联网账号或积分榜。

## 启动

需要完整 JDK 17+ 和 Maven 3.9+，首次构建需要联网下载依赖。请保留仓库中的 `fightinggame` 与 `multiplayer` 两个目录，构建时会引用共享战斗源码。

从仓库根目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\multiplayer\run.ps1
# 默认端口已占用时：
.\multiplayer\run.ps1 -Port 8081
# 手动指定构建工具目录：
.\multiplayer\run.ps1 -JdkPath 'C:\Java\jdk-21' -MavenPath 'C:\Tools\apache-maven-3.9.16'
```

打开 <http://127.0.0.1:8080/duel.html>，输入昵称加入席位。在另一个独立标签页打开同一地址加入另一席，双方点击“准备”后开始对战。顶部仍可进入画板和回声测试。关闭运行脚本的终端或按 Ctrl+C 停止服务。默认只监听本机 `127.0.0.1`。

同一局域网的多台设备测试时，可运行 `.\multiplayer\run.ps1 -BindAddress 0.0.0.0`，再通过 `http://服务器局域网IP:8080/duel.html` 访问；Windows 防火墙需要允许该端口。页面从自身地址连接 WebSocket，无需单独修改连接地址。当前是无账号的公共竞技场，暂不部署到公网。

脚本会查找显式指定的工具目录、环境配置和仓库 `.tools` 中的工具。页面资源和图标随 JAR 打包，运行时不需要 Node.js 或外部 CDN。

项目提供 `maven-settings.xml`，脚本使用其中的阿里云 Maven Central 镜像。也可使用系统 Maven 配置从该目录运行 `mvn test` 或 `mvn package`，无需使用该镜像。

```powershell
.\multiplayer\run.ps1 -Test       # 实际 HTTP/WebSocket 集成测试
.\multiplayer\run.ps1 -BuildOnly  # 测试并构建可执行 JAR
java -jar .\multiplayer\target\arena-multiplayer-0.2.0.jar --server.port=8080
```

该模块仍可独立运行。桌面版 1.1.0 的 `package.ps1` 会将服务 JAR 一起放入免安装包，玩家可在原生联机窗口创建房间。桌面构建使用 `build/server-build-*` 独立目录，避免占用正在运行的网页原型 JAR；手动构建也可传入 `-BuildDirectory` 指定输出目录。

## 双人格斗

- 一个公共竞技场、两个玩家席位，其余连接可观战。先加入者为 P1；双方准备后 P1 先手，再战时轮换先手。
- 双方采用均衡初始属性：180 生命、30 攻击、2 防御、3 瓶药水。技能沿用桌面版：普通攻击、强力一击、生命汲取、防御和治疗药水。
- 每次有效行动后交换行动方。非法操作不消耗回合或资源；只有自己的有效行动会推进技能冷却。
- 服务端校验席位、对局 ID、回合和技能条件，计算伤害、恢复及胜负。客户端传入的血量、伤害或玩家编号不作为战斗依据。
- 血量归零、认输或主动离席结束本局；双方同意后可以再战。200 个有效行动仍未结束时判平局；目前没有每回合行动倒计时。
- 网络断开后暂停战斗，保留席位 30 秒。原标签页刷新或自动重连会恢复席位、回合、血量和日志；超时判负并释放席位。准备阶段断线会取消该玩家的准备。
- 恢复凭据保存在该标签页的 `sessionStorage` 中。同一凭据在新连接恢复时会替换旧连接；浏览器的“复制标签页”可能复制凭据。双人测试请独立打开地址，不要复制已入席的标签页。
- 对局仅存在于服务内存中。服务重启会清空对局和恢复凭据，玩家需要重新入席；本地离线账号不会上传。

详细消息与状态约定见 [联机对战协议](DUEL_PROTOCOL.md)。

## 共享画板练习

- 固定 1200×720 逻辑画布，鼠标和触屏坐标按显示尺寸换算。
- 画笔、橡皮、六种颜色、1–32 像素粗细，以及 1200×720 PNG 导出。
- 多人实时绘画、在线人数、新用户快照与自动重连。断线期间禁用绘画和清空，保留最后收到的画面；重连后以服务端快照为准。
- 清空需要确认，影响所有在线用户；当前不提供撤销。
- 画面仅保存在服务进程内存中，**重启服务后会清空**。关闭网页后，只要服务仍在运行，重新打开就能恢复画面。没有房间隔离或多实例协调。

详细消息字段、事件顺序、容量限制和并发约定见 [画板协议](BOARD_PROTOCOL.md)。

## 回声协议

| 项目 | 约定 |
| --- | --- |
| 端点 | `ws://127.0.0.1:8080/ws/echo`；HTTPS 部署时使用 `wss://` |
| 请求和响应 | WebSocket 文本帧，UTF-8；收到什么返回什么，不封装 JSON |
| 保真 | 保留空文本、中文、空格、换行和 HTML 字面内容 |
| 消息限制 | 每条最多 4096 个 UTF-8 字节，超限关闭码 `1009` |
| 消息类型 | 二进制帧不支持，关闭码 `1003` |
| 来源 | 浏览器连接采用 Spring 默认同源检查；无认证功能 |
| 空闲连接 | 120 秒无收发后关闭，可手动重新连接；暂不做心跳或自动重连 |
| 连接隔离 | 消息只回复原连接，不存储消息或共享状态 |

浏览器按 UTF-8 字节计数，避免中文字符按字符数计算导致超限。日志保留最近 200 条，累计发送/接收计数不会因清空日志重置。往返时间由浏览器测量。消息使用 `textContent` 渲染，HTML 文本不会执行。

回声处理器不持有可变共享状态。共享画板使用独立的 `BoardHandler`，在同一把锁内更新状态、分配序号和投递事件；实际网络发送在每个客户端的独立线程中完成，不占用状态锁。

## 浏览器验证

先启动上述服务，并安装 Node.js 20+ 及 Google Chrome，然后运行：

```powershell
Set-Location multiplayer
npm ci --include=dev
npm test
# 如果服务使用其他端口：
$env:ECHO_BASE_URL = 'http://127.0.0.1:8081'
npm test
```

Playwright 在 1440×960 和 390×844 视口验证完整联机对战、技能状态、双方血量、胜负与再战、刷新和断线恢复、观战权限，以及原回声与画板操作。对战截图检查实际角色渲染和动画，画板测试对比不同客户端的 Canvas 像素。结果位于 `test-results/`，不会提交到 Git。

**浏览器测试会占用竞技场席位并清空公共画布。** 请另外启动 `.\multiplayer\run.ps1 -Port 8081`，设置 `ECHO_BASE_URL` 为该端口后运行测试，避免影响正在使用的服务。Java 集成测试自行启动随机端口，不影响运行中的服务。可用 `npm test -- duel.spec.cjs` 单独验证对战。

Java 测试覆盖对战合法性、冷却与药水、击杀结算、认输和再战、断线期限、并发操作、重复请求、伪造属性和观战越权，同时保留画板及回声回归。仓库根目录 `.\run.ps1 -Test` 验证共享技能规则在原桌面/控制台游戏中的行为。

本地 SVG 图标来自 Lucide，许可证在 `src/main/resources/static/icons/LICENSE.txt`。仅在更新图标时需要 `npm run prepare:icons`；图标文件已包含在源码中。
